# Parametric Pattern Plotter (PPP) — development notes

For contributors and coding assistants (Claude Code etc.). Read this before changing `index.html`.
User-facing documentation is in [README.md](README.md).

Browser-based parametric 2D CAD for leathercraft patterns. Repo `amber-color/parametric-pattern-plotter`
(was `leather-pattern-cad`), served by GitHub Pages from `main` at https://amber-color.github.io/parametric-pattern-plotter/.
Push straight to `main` when asked; there is no build step.

## Working style
- The owner writes in casual, brief Japanese; reply in Japanese, plain and short. For small changes describe the diff, not a rewrite.
- Always commit and push every finished change straight to `main` without asking, unless the owner says otherwise.
- UI wording is Japanese first; every new on-screen string also needs English (see i18n below).
- Ask before big design decisions; small UI tweaks (colours, labels, icons) are applied directly and shown with a screenshot.

## Data model (what `.json` files, share links and the code panel hold)
`doc = {name?, vars:[{n,e}], shapes:[…]}`; every dimension is an expression string. `name` is the project name
(top bar `#projName`; `fileBase()` turns it into file names, `showName()` keeps the field and the tab title in step).
- Axes: the drawing (doc values, references, the panel, the status bar, DXF) has y **up** and counter-clockwise
  rotation; a rect's `x,y` is its bottom-left corner. Inside, geometry and the canvas run y **down** as before (screen /
  SVG / PDF terms), so the flip happens only where doc values are read or written: `geomLeaf0` / `evalNodes` / `rotOf`
  negate y, rot and rcy (rect: top = -(y+h)); `shapeProp` / `selfProp` return y values negated (上 = -min y);
  writes go through `eyOf` (num(-y)), `shiftLeaf` / `shiftPivot` (move by -dy), and the handle / draw / node code.
  Stitch `eo` / `fl` / piece anchors `u,v` are in internal bbox terms and did not change.
- `image` shapes (下絵): `p.x, p.y` (bottom-left), `p.w`, `p.h` (empty = `w*ar`), `ar` (the picture's height / width), `op`;
  resized with the rectangle's `rs-` handles (Shift keeps the proportions, writing plain numbers). The picture (a shrunk JPEG data URL)
  is kept out of the doc in `IMG` and IndexedDB (`IDB`, key `img:<id>`), written into a saved .json as the shape's `img`
  (`takeImgs` moves it out again on open), copied on duplicate / paste, and never put in a share link. Images are drawn first,
  are never exported or snapped to, and a drag on a locked one box-selects. The first version's `doc.under` migrates to an
  image shape `img_under`.
- Shape flags `hide` (not drawn, not hit, not snapped to; exports unchanged) and `lock` (no drag, handles or delete).
- ⌘C / ⌘V use the copy / paste events: `clipOf` (selection + `moveTree` + used variables) and `pasteClip` (new ids, unique
  names, references between pasted shapes rewritten by `remapRefs`, moved 10 mm).
- A path's `p.x, p.y` is its origin (empty = 0): `placedNodes` adds it to the nodes, moving a path (`shiftLeaf`) changes only
  the origin, and node values written from the canvas go through `nodeX` / `nodeY` / `nodeXE` / `nodeYE` (relative to it).
  `自分.点1X` reads the node field as written (relative); other shapes' `L.点1X` read the placed value.
- shape: `{id,name,type,kind,p:{…},st:{on,inset,pitch,hole,method?,pos?,eo?},fill?:{t,pitch}}`; `kind` is a line type from
  `LINES` (cut 実線, thin, red, guide 破線, dashthin, chain — cut/guide are the old 裁断線/ガイド ids), `fill.t` a hatch from
  `HATCHES` (`hatchOf` clips lines / places dots in world coordinates, used by canvas and all exports)
- types: `rect` (x,y,w,h,r; `ct` round|chamfer; `cmode:'each'` + `cs[4]{t,r}`), `circle` (cx,cy,d), `ellipse` (cx,cy,w,h; rotatable), `arc` (cx,cy,r,a1,a2: counter-clockwise degrees, `arcSweep`; open),
  `poly` (`nodes:[{x,y,t?,hi?,ho?,r?}]`, `closed`; `r` rounds a corner node — `filletNodes` turns it into two tangent
  points and a two-piece Bézier arc in `g.fnodes`, while `g.nodes` stays as written for editing and references), `bool` (`op` union|diff|inter|xor, `ops:[ids]`, materials stay as shapes),
  `offset` (`src:[ids]`, `op` for several sources, `side` out|in, `join` round|miter, `p.d` distance; the sources stay
  ordinary shapes — not materials — and dragging, duplicating or mirroring an offset carries its sources along),
  `piece` (分割: `src`, `cut:[ids]`, anchor `u,v` in the source's bbox; `splitPieces` takes 2 µm slivers along the cuts out
  of the source and `geomPiece` picks the part holding the anchor; source and cutters count as its materials via `parent`),
  `text` (text; x,y,size,rot), `dim` (x1,y1,x2,y2,off,size). rect/poly/bool may have `rot`, `rcx`, `rcy` (pivot).
- corners: a node or `fl` entry with `ct:'chamfer'` is cut straight, `r` from the corner along each edge (`chamferAt`, `cornerAt`);
  the fillet tool's `#fMode` picks round or chamfer.
- fillets on bool / offset outlines: `fl:[{u,v,r,ct?}]`, anchored to the corner in the unrounded outline's bbox (`g.lbb0`) like
  `st.eo` (`filletOutline`). The fillet tool (`doFillet`) writes `node.r`, a rect's `cs[i]`, or `fl`, or joins two open
  paths / drops the nodes between two edges of one path (`pendingBetween` offers keeping them as a line).
- stitching and operations: every non-bool shape, materials included, is stitched on its own outline (drawn at full
  strength even when the material is faint, exported regardless of the materials checkbox). A bool is stitched on its
  own outline only while no material has stitching on (`matStitchOn`; a piece's materials are its source and cutters, `matsOf`); otherwise its st is kept but unused. `bake`
  keeps a bool's own stitching, or moves the materials' per-edge settings onto the baked outline with `edgeMapper`.
- per-edge stitch overrides: `st.eo:[{u,v,off?,pitch?,method?,pos?,from?,to?,gaps?:[{at,len,end?}]}]` (gaps: unstitched runs, from the start or with end:1 from the end), anchored to the edge midpoint in the
  unrotated bbox (0..1) and matched to the nearest edge on each compute (old `st.edges` is migrated).
- export: `exportItems(opt)` decides what goes out (`UI.exp[pdf|svg|dxf]`, keys in `EXP_KEYS`, defaults `EXP_DEFAULT`)
  and skips shapes with `s.noexp`; each item says whether to draw the shape, its holes, stitch line and name.
- storage keys: `ppp-v1` (doc), `ppp-ui` (UI: varsCollapsed, pdfSize/pdfOrient, exp, showFrame, osnap, theme, lang).
- share link: `#p=` + `z`+base64url(deflate-raw JSON) or `j`+base64url(JSON).

## Expressions
Own tokenizer/parser (`tokenize`, `evalExpr`): + - * / ^ ( ), sqrt sin cos tan atan abs min max round floor ceil, pi.
Names are Unicode; may start with digits when a letter follows (`500円玉直径`); digits-only names are rejected.
Shape references: `外装.右`, `[名前（記号入り）].上`, `ベロ.点3X`, `自分.幅` (self). English aliases are accepted
everywhere (`right`, `width`, `centerX`, `pt3X`, `self`); Japanese is canonical, `propIn`/`propOut` convert.
`compute()` gives each shape an env from `selfEnv` (guarded per field, so self-loops are errors); `$ref` resolves shapes
with cycle detection. Variables cannot reference shapes.
Panel and variable expression fields get a suggestion list as you type (`sgItems`/`sgShow`/`sgPick`): variables,
shapes (then their values after the dot), functions, pi. A variable's field only offers the variables above it. Picks go in
through `execCommand('insertText')` so the field's own undo keeps working; keys are handled in the capture phase and left
alone while an IME is composing.

## Things that are easy to break
- Snapping writes references (`exOf`/`eyOf`); alignment guides never create references; rotated shapes are snapped
  to by number only.
- `CENTRED` types are placed by cx / cy; `CURVY` types (poly, ellipse, arc) export their Bézier `g.fnodes` / `g.nodes` instead of the
  sampled outline (an arc also goes to DXF as ARC). The arc tool takes three clicks (`arc3`).
- Trim tool (`tool==='trim'`, `#tMode` trim | extend | break): a path or an arc is measured by u (segment index + t, or degrees from a1);
  `trimCuts` finds where other outlines cross it, `polyRun` rebuilds the nodes of a run (whole nodes keep their expressions, cut ends are
  numbers) and `applyRuns` writes the runs (extra runs become new shapes). `joinPicks` chains open paths / arcs whose ends meet; the line that stays is one other shapes build on or refer to beyond its
  nodes (else the first picked), node references (`点N` / `始点` / `終点`) move onto the joined path's new indices, and a join that
  would leave the path in error is rolled back.
- dims: `dt` absent = length; `dt:'ang'` (x1,y1 vertex, x2..y3 a point on each side, off = arc radius; `angParts`); `dt:'rad'|'dia'`
  (cx, cy, r referring to the circle / arc, ang = direction; `radParts`). All give `g.dim` {lines, arrows, text}, so the exports need nothing
  per type (DXF writes ° / Ø as %%d / %%c; the PDF font uses WinAnsiEncoding). The dim tool's `#dMode` picks the kind.
- Numeric input (`#numBox`, `numKind` / `numPlan` / `applyNum`): digits or Tab while drawing open one field per value (Tab moves,
  an empty field takes the cursor's value); after a click that leaves a second point to give they open by themselves (`autoNum`, mouse
  only), and while still empty they hand Enter / Esc / Backspace / tool letters back to the document; `lastPt` is the cursor over the canvas. Rectangles, ellipses and circles also draw by two
  clicks (`draft.clicked`, `finishBox`), and after the first click the typed sizes run toward the cursor (`numSide`).
- Move / copy by distance: rail tools `move` (M) / `copy` (C); `moveBegin` takes the selection or lets the next click pick
  (`mvop.picking`), then `mvop` {ids, base}; the destination is clicked (`moveDest`) or typed
  (numeric kind `mv`). Moving goes through `shiftShapes` (also used by alignment); copying through `pasteClip(clipOf(), dx, dy, true)`.
  Shifts skip expressions that refer to a shape moving by the same amount (`followsIn`, `shiftLeafBy`), so a hole placed at
  `A.中心X` isn't moved twice when A moves with it (drag, align, move, paste).
- Rail tool `array` (Y) opens the array dialog for the selection, or for the next shape clicked.
- On desktop the rail's tools shrink (down to 30px) before the rail scrolls (`.rail .tool{flex:0 1 40px}`).
- Positions are rewritten through `moveLeaf(c, fx, fy)` (fx / fy map each x / y expression; `shiftLeaf` is the numeric case).
  `cloneTree(s, mv)` takes a number (shift right) or `{fx, fy}`; array copies (`doArray`) use it with `combE(e, spacing, 1, k)`
  so a spacing expression stays an expression. Alignment (`alignPicks`) moves each pick's `moveTree` like a drag.
- Rect / image side handles: an X or Y written from the shape's own size (`100-自分.幅`) stays as written and the size is solved
  for the dragged side (`selfLin`); writing `combE(X, 幅)` back into 幅 there would refer to itself. As a net for every handle drag,
  a step that leaves the shape in error is undone (`drag.last`, a second pointermove listener).
- Moves rewrite expressions with `shSmart` (adjust a trailing constant); a drag that changed expression positions asks
  for confirmation (`mvModal`).
- Japanese IME: never act on Enter while composing (`composing(e)`), or text is committed twice.
- `render()` rebuilds the panel unless a panel text field has focus with the same selection key (`lastPanelKey`).
- bool and offset share `combine(op, outlines)`; `moveTree` lists what moves with a shape (bool materials, offset sources),
  `blockedBySrc` stops deleting a shape an offset uses.
- Relationship graph (関係図, `body.graphmode`, pane `#gpane` under the canvas): `graphData` builds nodes (vars, shapes)
  and edges (expr / ref / mat) and lays them out in columns by longest input chain; `graphSync` (called from `render`)
  redraws only when the structure key changes, otherwise `updateGraph` refreshes values, previews, errors and selection.
  Slider ranges must sit on whole steps (`gRange`) or the browser moves the value itself.
- Avoid short global names: `L` is used as a local in many places (a helper named `L` once broke rect creation).

## i18n
`LANG` from `ppp-ui.lang` or the browser. The UI is written in Japanese; in English mode a MutationObserver swaps
on-screen text through `EN_EXACT` (exact strings) and `EN_PAT` (patterns with {0}…; captures stay as written unless
marked `{n:'T'}` or given a word map). Names users type are never translated. `#shapes`, `#helpBody` and elements with
`data-noi18n` (the code editor) are skipped. New Japanese text on screen → add it to `EN_EXACT`/`EN_PAT`.
Key names are written Mac-style (`⌘Z`, `⇧⌘Z`, `Ctrl / ⌘`); off Mac, `kb()` rewrites them to `Ctrl+Z`, `Ctrl+Shift+Z`, `Ctrl`
in the same pass (and in the guide), so write new shortcuts the Mac way.
Default names for new shapes go through `nm()` / `EN_NAME`.

## Layout
Desktop grid: tool rail | canvas | parts panel (only with a selection) | variables bar (collapsible). The code panel
(`body.codemode`) replaces both side panels. Phones (≤760px): one screen, canvas on top, bottom 44dvh shows the parts
panel when something is selected, else the variables (or the code panel). Touch: two-finger pinch/pan, one finger on
the background box-selects; the first finger's action is undone when a pinch starts.
Panel sizes: `.sizer` handles on the parts / variables / code panels and the graph pane write `UI.sizes`
(`pw vw cw` px, `gh` %, `mh` dvh on phones) and `applySizes` sets them as CSS variables `--pw` etc. on `<html>`.
